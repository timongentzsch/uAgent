## apply_patch

Offered: always. Parallel: no.

## run

Offered: always. Parallel: yes.

Execute a command in cwd; omit cd. tty=true enables interactive stdin; detach persists a terminal beyond this session. Bash/zsh pipelines propagate failures (pipefail); nested scripts must also return a failing exit status for failed checks. A command still running when this returns becomes an activity whose result starts your next turn when it ends: end the turn instead of waiting unless your next step needs it; to check back later, start sleep N this way.

| Parameter | Type | Required | What |
| --- | --- | --- | --- |
| `command` | string | yes |  |
| `description` | string | yes | what it does in a few words, imperative: Run the unit tests |
| `detach` | boolean |  | persist terminal and log |
| `max_output_chars` | integer |  | returned-output cap; prefer this over piping through tail/head |
| `sandbox` | boolean |  | false runs outside the OS sandbox; always asks a person |
| `shell` | string |  | default bash |
| `tty` | boolean |  | retain an interactive PTY |
| `yield_ms` | integer |  | initial wait; 0 blocks to deadline; omitted waits 10000 |

## browser

Offered: a top-level session while the web host runs the browser. Parallel: no.

Read and use any page as a person would: pages web_fetch leaves short (built by scripts, behind a login, cut off), forms, sign-ins and downloads. This is the shared persistent Google Chrome that the web host runs; the user sees and can drive the same browser. release when done so other conversations can use it; when the user turns on research browsers (signed out), browser=shared asks for this one. open, click, type (into the focused field), press, drag, scroll, back, forward and reload wait for the page to settle and return it as text: its numbered elements, its text and a view_id. click takes element (a number from a result) and that result's view_id; a number stays good on the same page, so one look serves several actions, such as filling a form in one step. click takes button=right for a context menu and count=2 for a double click. drag holds the button from element (or x and y) to to_element (or to_x and to_y), for sliders, sortable lists and drag-and-drop. press takes a key name, or one character, after any of Control, Shift, Alt and Meta joined by + (Control+A, Shift+Tab). Fill a field in one call: type with element and view_id clicks it first, replace=true overwrites what it holds, and key is pressed after. type sets a list to the option whose label it gives, and a date, time or color field to the value the page receives, such as 2027-03-12 or 19:30. batch runs steps (click, type, press, scroll, drag) in order on the page of view_id, stops at the first failure and returns the page once: fill a form or walk a checkout in one call; its element numbers hold for every step, x and y only for the first. read returns the full page, or more: page text from offset (in characters), or with find the lines and links that contain it, whatever their case, 200 lines at a time from match offset. open takes the same offset or find and then answers as read does, for a page you only need to read; several such calls in one step read several pages. observe adds a screenshot, for a page that text does not describe; where no element number fits, click takes x and y in its CSS pixels, and scroll takes them with delta_y, each with the latest view_id. A tab opened by your action becomes active automatically; open with new_tab=true keeps the current page; tabs lists tabs, switches to target_id, and with close=true closes it instead, unless it is the current one. To look at a page you wrote, open takes path instead of url: an .html or .svg file; one in this conversation's folder loads its stylesheets and images as the canvas shows it, and reports its problems (file:// URLs are refused). observe with a deck folder returns a numbered overview and each slide's layout problems, 8 at a time (part=9-16); part=3 zooms into one slide. With a page path it shows its pages or tabs, or crops the picture to a CSS selector. upload with element, view_id and path gives a file of this conversation's folder to a file field, or to the chooser the element opens; what a page downloads lands in its downloads folder. console returns the page's console messages and uncaught errors, network its requests since it loaded; find narrows both. Chrome holds the user's saved logins: on a sign-in page click the field, call fill_saved to take the one Chrome offers for it, then submit what Chrome filled. Where the user has several accounts, type the start of the wanted account's name into the field first: Chrome then offers the ones that match. Never type or repeat a password. For a login Chrome has not saved, MFA, captchas, bot checks or payment confirmation, call request_human with a reason naming the site and step; it waits until the user hands back. Never ask for credentials in chat. Required per action: click: view_id; press: key; scroll: view_id; drag: view_id; upload: element, view_id, path; batch: view_id, steps.
